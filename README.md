# Sportel

**Raporto një herë, provo çdo numër.** Report once, prove every number.

Sportel turns the exports that municipal directorates already produce (CSV, XLSX, XLS) into
performance indicators. Every number carries its proof: the formula, the SQL, the source file and
the source rows. When data is missing, Sportel names the missing export and the directorate that
owns it. It never guesses a number.

Built by **FirmatGroup** at the AI4Society Youth Innovation Hackathon (Tirana, 25–27 Sept 2026),
**Track D: Municipal Data Integration & Decision-Support Dashboard**, for the Municipality of
Elbasan. The repository folder is still called `elbasan-pulse`, the product's earlier name.

> **Demo data is synthetic.** Every file in `api/samples/` was generated by
> `api/scripts/generate_samples.py` with a fixed seed. Each one has `SINTETIKE` in its filename
> and title row, and the header shows **Të dhëna sintetike** (synthetic data) whenever a loaded
> source is synthetic. None of these figures are official Elbasan figures. The synthetic
> population totals are deliberately different from the official census and civil-registry
> totals.

## What it does: the gap-to-proof loop

1. **Board (`/`, Paneli).** A counter shows how many indicators have proof (6 of 13 after a
   demo reset). Computable tiles show a value, a target status, a sparkline and any signals. Grey
   tiles read *Mungon eksporti · Përgjegjës: …* (export missing · owner: …).
2. **Honest refusal (`/ask`).** Ask the question behind a grey tile. The answer is **Pa përgjigje**
   (Not answerable). It names the missing export and its owner and says that no number was
   guessed.
3. **Ingest (`/ingest`).** Drop the export in. Code reads the file, finds the header row and the
   units (such as `(000 lekë)`), sets aside title, blank and total rows, and drops personal
   columns. It then profiles the remaining columns. A model (or, without a key, deterministic
   rules) proposes which column means which field. A person confirms, and the **Load Receipt**
   checks that rows read = loaded + excluded and that the sums match the file's own total row.
4. **Same question, now proven.** Ask again. The answer is **E verifikuar** (Verified). It shows
   the value computed by code, an "interpreted as" chip, the SQL, and the source files with row
   ranges. The tile turns green and the counter goes up.
5. **Report with sources.** **Shkarko raportin (.xlsx)** downloads a workbook. On sheet
   `Treguesit`, a visible `Burimi` (source) column next to every value names the file, the rows,
   the passport version and when the value was computed. Sheet `Burimet` lists the source files
   with their hashes.

The files look like real municipal exports on purpose: merged title rows, units in headers,
`TOTALI`/`Gjithsej` rows, Albanian dates and decimal commas, and spelling variants of
administrative units. Two files contain **clearly fake** personal-looking columns (invented
short names, phone numbers in the pattern `+355 69 000 xx xx`) so that the personal-data gate has
something to drop. None of it is real personal data.

**Using the organisers' data package.** Nothing is hardcoded to the synthetic files except the
demo seed list in `api/samples/manifest.json`. A package file that maps to one of the six
canonical datasets (`api/app/catalog.py`) goes through the same pipeline: drag it into `/ingest`,
or put it in `api/samples/` and add it to the manifest with `"synthetic": false`. Its receipt,
lineage and indicators then come from that file. A dataset or indicator that the catalog does not
know yet needs a catalog entry and a passport (a code change).

The UI is Albanian by default, with an English toggle. It supports light and dark themes,
keyboard navigation and reduced motion.

## Architecture

```
department exports (CSV / XLSX / XLS)
  │  /ingest: read → header & units → set aside title/blank/total rows → personal-data gate
  │           → profile → recipe lookup (header fingerprint) → mapping (AI model, or rules)
  │           → person confirms → load with source_id + row_no → reconcile → Load Receipt
  ▼
DuckDB (one file): canonical tables + source receipts, mapping recipes, llm_call log, pins
  ├─ indicator passports (versioned YAML: formula, SQL, lineage SQL, owner, checks, target)
  │     → board, passport, signals, .xlsx with "Burimi", open-data CSV
  ├─ SMP 2024 Annex A coverage pack (states and owners only, nothing computed)
  └─ copilot /ask: example → passport │ free text → matcher, or AI intent (AI LIVE only)
        → passport SQL (verified) or one guarded SELECT in a sandbox (exploratory);
          the label and the answer text come from code
  ▼
REST API /api/v1 (FastAPI, OpenAPI at /docs) → Next.js 16 web app (sq/en)
                                               └─ REPLAY: recorded API responses if the API is down
```

| Path | Contents |
|---|---|
| `api/app/catalog.py` | Datasets, fields, synonyms, owners (role placeholders), admin-unit normalisation, number/date parsing |
| `api/app/ingest/` | Reader, layout (header/units/totals), personal-data gate, profile, recipes, mapper, pipeline, routes |
| `api/app/indicators/` | Passport registry, evaluation, signals, SMP coverage, `.xlsx`/CSV export; packs in `packs/core_kpi.yaml` and `packs/al_smp.yaml` |
| `api/app/copilot/`, `api/app/sqlguard/` | `/ask`: examples, matcher, intent, answer templates; sqlglot guard and in-memory sandbox |
| `api/app/llm/client.py` | The single Claude client: structured output, cost, persisted call log, budget, RULES fallback |
| `api/app/warehouse/` | DuckDB connection and schema |
| `api/scripts/` | `generate_samples.py`, `seed_demo.py`, `run_eval.py` |
| `api/tests/` | pytest suite, including the 24-question golden set (`tests/golden/`) |
| `web/src/app/`, `web/src/components/sportel/` | Routes and screens |
| `web/src/lib/api.ts`, `client.ts`, `fixtures/` | Typed API client (mirrors the contract), live-or-REPLAY switch, REPLAY engine and snapshot |
| `web/messages/{sq,en}.json` | UI strings |
| `web/scripts/` | `check-live.mjs` (end-to-end contract check), `record-replay.mjs` (re-records REPLAY) |

Stack: Python 3.12, FastAPI, DuckDB, openpyxl, sqlglot, RapidFuzz, OpenAI and Anthropic SDKs; Next.js 16,
React 19, Tailwind CSS 4, next-intl, Apache ECharts, lucide-react.

## Run it

Prerequisites: Python 3.12 with [uv](https://docs.astral.sh/uv/), Node 22 with pnpm 10, and
`make` (optional: every target is a one-line command, listed below).

```bash
cp .env.example .env          # docker compose reads this
cp .env.example api/.env      # the API reads this when run from api/
# For live AI, put OPENAI_API_KEY=... (the organisers' key) and
# OPENAI_BASE_URL=https://llm.mjovanovic.dev/v1 in both files, then check it with
# `cd api && uv run python scripts/check_llm.py`. Without a key everything runs in RULES mode.

make install                  # uv sync + pnpm install
make seed                     # fresh demo database: requests, budget, population (6/13)
make dev                      # API on :8000, web on :3000
```

Open <http://localhost:3000>. API docs are at <http://localhost:8000/docs>.

| Target | What it does | Without make |
|---|---|---|
| `make install` | Install API and web dependencies | `cd api && uv sync` · `cd web && pnpm install` |
| `make dev` | API (reload) on :8000 and web on :3000 | `cd api && uv run uvicorn app.main:app --reload --port 8000` · `cd web && pnpm dev` |
| `make seed` | Reset the database offline to the demo start state, 6/13 (**stop the API first**: DuckDB allows one writer process) | `cd api && uv run python scripts/seed_demo.py` |
| `make seed-all` | Same, plus envelopes 1–3: 13/13 | `cd api && uv run python scripts/seed_demo.py --all` |
| `make demo-reset` | Reset a **running** API to the start state (also clears recipes) | `curl -fsS -X POST http://localhost:8000/api/v1/demo/reset` |
| `make eval` | Run the 24-question golden set and write `api/eval_result.json` (served at `/ask/eval`) | `cd api && uv run python scripts/run_eval.py --mode auto` |
| `EVAL_MODE=rules make eval` | Same, ignoring any key | `… run_eval.py --mode rules` |
| `make test` | pytest and the web tests | `cd api && uv run pytest -q` · `cd web && pnpm test` |
| `make lint` | ruff check, ruff format check, eslint | `cd api && uv run ruff check . && uv run ruff format --check .` · `cd web && pnpm lint` |
| `make samples` | Regenerate the synthetic exports (same bytes every time) | `cd api && uv run python scripts/generate_samples.py` |

On Windows, Git Bash has no `make`. Use the right-hand column. If the pnpm shim fails in Git
Bash, run `cmd //c "pnpm --dir web dev"`.

**Docker.** `docker compose up --build` builds both images. The API container seeds the demo
database on first start (only when it is empty) and keeps it in the `pulse-data` volume. The web
image bakes in `NEXT_PUBLIC_API_URL=http://localhost:8000`. For a live demo we use localhost.

**Hosted demo.** Web on Vercel: <https://sportel.vercel.app>. API on Render (free plan):
<https://sportel-api.onrender.com> (docs at `/docs`).

- **API (Render).** `render.yaml` is a Blueprint that builds `api/Dockerfile` from
  `AI4Society-Hachathon/Team-Firmat` and redeploys on every push to `main`. Set `CORS_ORIGINS` (the
  Vercel URL) and optionally `OPENAI_API_KEY` in the Render dashboard. The free plan sleeps
  after 15 minutes without traffic (the first request then takes about a minute) and has no
  persistent disk, so each start re-seeds the demo state (6/13). The LLM spend counter also
  restarts from zero. Open `/api/v1/health` a minute before a demo.
- **Web (Vercel).** Project `sportel` with root directory `web`, built from
  `greisikertuka/sporteli` (Vercel's Hobby plan cannot build private organisation repos). The
  production branch is `main`, and `NEXT_PUBLIC_API_URL=https://sportel-api.onrender.com` is set
  in the project. Push `main` to both remotes so the web app and the API stay on the same commit.

**Web-only checks.**

```bash
pnpm --dir web build
pnpm --dir web check-live http://localhost:8000 http://localhost:3000   # walks the whole loop; RESETS that API's data
pnpm --dir web record-replay http://localhost:8000                      # re-records REPLAY; also resets
NEXT_PUBLIC_USE_FIXTURES=1 pnpm --dir web dev                           # forced REPLAY, no API needed
```

## API overview

Base path `/api/v1`. The JSON shapes are defined in the build contract (§7) and mirrored in
`web/src/lib/api.ts`. Every user-facing string is `{ "sq": "…", "en": "…" }`. Errors are
`{ "detail": { "code", "message": { "sq", "en" } } }` with a 4xx status.

| Method and path | Purpose |
|---|---|
| `GET /health` | Status, database, AI mode (`live`/`rules`), spend, budget, synthetic flag |
| `GET /datasets` | Canonical datasets with owner, fields, load state and the indicators each unlocks |
| `GET /samples` · `GET /samples/{name}/file` · `POST /samples/{name}/preview` | Server-side sample files |
| `POST /ingest/preview` | Multipart `file` (CSV/XLSX/XLS, up to 15 MB): steps, columns, personal-data result, mapping, recipe/drift |
| `POST /ingest/remap` | Re-propose the mapping for another dataset |
| `POST /ingest/commit` | Load with the confirmed mapping; returns the Load Receipt |
| `GET /ingest/recipes` · `DELETE /ingest/recipes` | Saved mapping recipes (delete is demo-only) |
| `GET /sources` | Every loaded source with its receipt and mapping |
| `POST /demo/reset` | Back to the start state, 6/13 (demo-only) |
| `GET /indicators?pack=core_kpi` | The board: coverage, tiles, signals, sparklines |
| `GET /indicators/{code}` | One passport: value, formula, SQL, series, lineage, checks |
| `GET /indicators/{code}/lineage?limit=50` | The contributing source rows |
| `GET` · `POST /definitions/population_basis` | Read or pin the population basis (`census_2023` / `civil_registry`) |
| `GET /coverage?pack=al_smp` | SMP 2024 Annex A coverage states |
| `GET /export/core_kpi.xlsx` | Workbook with the `Burimi` column, the `Burimet` sheet and cell comments |
| `GET /open-data/indicators.csv` | Computable indicators with value, period, basis, sources, version (`X-License: CC-BY-4.0`) |
| `POST /ask` · `GET /ask/examples` · `GET /ask/eval` | Copilot, example questions, last eval result |
| `GET /llm/calls` | Spend, budget, mode and every logged AI call with a summary of what was sent |

```bash
curl -s http://localhost:8000/api/v1/indicators/REQ-02
curl -s -X POST http://localhost:8000/api/v1/ask -H "Content-Type: application/json" \
  -d '{"question":"Sa përqind e kërkesave zgjidhen brenda afatit?","locale":"sq"}'
```

## AI and privacy

**What AI does** (only when an API key is set, accepted by the provider, and the budget is not spent):

- **Column mapping (OpenAI `gpt-5-mini`, or Claude Haiku 4.5).** One structured-output call per file proposes a field
  for each column, with a confidence, a reason and at most one clarifying question. Mappings
  below 0.8 confidence need a click.
- **Reading free-text questions (OpenAI `gpt-5-mini`, or Claude Sonnet 5).** One structured call turns the question into
  an intent: a passport code, or a single SELECT. The model never writes the answer. Example
  chips skip the model entirely.

**What code does:** reads and cleans files, detects units and total rows, drops personal
columns, computes every indicator value, lineage and reconciliation, runs the plausibility
checks (signals), and **decides the label** of every answer: `verified`, `exploratory`,
`blocked` or `not_answerable`. Answer text is filled from templates with numbers formatted by
code. If a model-written "interpreted as" text contains a digit, code replaces it.

**What is sent to the model:**

| Call | Sent | Never sent |
|---|---|---|
| Mapping | Column headers and inferred types; masked sample values only if `LLM_SEND_SAMPLES=true` (off by default) | Rows (`rows_sent: 0`), personal columns |
| Question intent | The question text (up to 1,000 characters), the list of passports, the schema of the allowed tables | Any data row |

- **Personal-data gate.** Columns that hold names, phone numbers, e-mail addresses, Albanian
  personal numbers or street addresses are detected by header keywords and value patterns. They
  are dropped **before** profiling and before any model call. They are never loaded.
- **Blocked before the model.** Questions that ask for personal data or ask to change data
  are blocked by code before any model call. The SQL guard (sqlglot) allows exactly one SELECT
  over the allowlisted tables, with no table functions, file access or pragmas, and wraps it in
  `LIMIT 200`. The query runs in an in-memory DuckDB with external access disabled.
- **Call log.** Every call that reaches the API is written to `llm_call` with its cost, latency
  and a summary of what was sent. `/trust` and `GET /llm/calls` show it.
- **RULES mode.** With no key, or once the budget is spent, the header shows **RREGULLA**.
  Mapping uses synonyms and fuzzy matching, with confidence capped at 0.6, so every column needs
  a click. Example questions work as normal. Free text that the deterministic matcher cannot
  route returns *AI jashtë linje — provo një pyetje shembull* (AI offline, try an example
  question). Nothing leaves the machine.
- **Budget.** `LLM_BUDGET_USD` (default 20). Spend is restored from the call log at start-up, so a
  restart does not reset it. Successful question intents are cached in memory, and a cached
  answer is badged **CACHED**.

## Limits

- The demo data is synthetic. Sportel proves consistency and lineage, not that a department's
  file is true.
- Every formula is our reading of public definitions and is marked **draft, awaiting
  validation** until the municipality's Performance Unit or AMVV validates it. Owners are
  role-based placeholders, to be confirmed with the municipality.
- The SMP coverage map is a draft pending organiser approval. Indicators #41–52 are computed
  nationally by AMVV from Ministry of Finance data, and Sportel does not compute them.
  Document-check indicators need a link and a person's confirmation.
- The accuracy figure comes from our own frozen set of 24 questions (12 Albanian, 12 English,
  including traps). It is indicative, not a benchmark. `GET /ask/eval` returns the latest run and
  its mode.
- The LLM client calls OpenAI (the organisers' key) or Anthropic. There is no local-model option
  today.
- In AI LIVE mode the text of a free-text question goes to the model. Do not type personal data
  into questions.
- The code has **no authentication, passcode or rate limiting**. A shared or hosted instance
  needs protection at the host and `DEMO_RESET_ENABLED=false`. The live demo runs on localhost.
- DuckDB allows one writer process: stop the API before `make seed`.
- Sportel predicts no grant points or money and is not an official submission channel.
